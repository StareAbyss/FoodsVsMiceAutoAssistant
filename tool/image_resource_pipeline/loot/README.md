# 战利品资源获取与名单管理

## 正式数据

三份 CSV 均位于 `resource/image/item/`，以“类型,名称”标识物品；名称不含 PNG 后缀。

- `道具可掉落-白名单.csv`：维护者手动确认可掉落的物品。
- `道具可掉落-黑名单.csv`：维护者手动确认不可掉落的物品。
- `道具可掉落-未分类.csv`：工具生成，列出范围内既不在黑名单、也不在白名单的物品。

黑白名单不由工具自动增删，也不在运行时自动初始化。每轮正式运行按“类型、名称”稳定排序两份人工名单，保留重复行与附加列，已排序文件不重复改写；`--dry-run` 不排序或写文件。两份名单重叠的物品报错，并暂停该物品的同步和清理；其余物品继续处理。名单缺失或格式错误时中止，避免误清理正式资源。

正式模板只保存在 `resource/image/item/战利品/类型/名称.png`。运行时也按白名单过滤，并排除黑名单冲突；修改名单会使战利品匹配缓存失效。

## 标准入口

从项目根目录运行：

```powershell
uv run python -m tool.image_resource_pipeline.loot
```

默认完成整轮流程：

1. 获取 `resource/db/` 中的原始数据快照；按文件名日期、时间选择最新 Excel。
2. 按既有 ID 前缀、技能书配方规则和精确物品例外筛选范围；合并同类型、同名称的重复记录。
3. 先把图片下载到 `resource_other/图像资源_战利品_最新资源/`，避免未审核模板进入正式库。
4. 生成未分类名单。历史正式模板和尚未处理的本地候选也纳入范围，不因最新表缺少条目而丢失。
5. 将未分类图和白名单图一起与失败样本匹配，计算候选分差，生成白名单建议。
6. 将有效白名单图片同步到正式库：同内容不改动，不同内容直接原子替换；下载或校验失败时保留原正式模板并报告。
7. 清理正式战利品目录内非白名单图片；退出正式库的未分类图片先保留到候选目录。
8. 候选目录只保留未分类图片；黑名单图片与白名单候选副本清理。冲突图片暂不清理。
9. 输出未分类提醒、白名单建议、同步数量和异常。

白名单图片每次正常联网运行都重新获取，不因本地已有图片而跳过。仅完整且可解码为 44×44 RGBA 的 PNG 可更新正式模板，包括带透明通道的索引 PNG；不兼容的未分类图仍保留供人工检查。未分类项目没有 URL 时仍进入待办，并明确显示缺图；这类来源缺失属于待核验提示，不冒充下载成功。

## 常用参数

- `--dry-run`：只打印分类预览，不联网、不改名单、不下载或清理图片。
- `--offline`：使用本地快照和候选，白名单候选副本已清理时使用正式图作为本地缓存；仍会执行同步和清理，不代表已检查最新 CDN 内容。
- `--excel resource/db/指定快照.xlsx`：固定该表，本轮不刷新 Excel，避免替换快照时删除所选输入。
- `--force`：未分类等已有候选也重新下载；白名单默认始终重新下载。
- `--manifest 路径.csv`：额外输出下载明细；默认不生成多份比对表。

Excel 仅从 `resource/db/` 读取，不搜索或回退根目录。数据库访问凭据只读取项目根目录被 Git 忽略的 `image_resource_db.local.json`，不得复制到资源目录或发行包。

## 默认产出与人工操作

- `resource/image/item/道具可掉落-未分类.csv`：待手动分类项目，包括尚无 URL 或下载失败的项目。
- `resource_other/图像资源_战利品_最新资源/类型/名称.png`：未分类图片，用于快速核验。
- `resource_other/战利品识别失败分析/白名单建议.csv`：多次完美匹配的未分类物品及证据。
- `resource_other/战利品识别失败分析/运行摘要.md`：数据源、同步结果、提醒和错误。

确认物品后，维护者将其“类型,名称”写入白名单或黑名单，再次运行工具。未分类名单由工具重新计算，无须人工维持三份名单一致。未分类文件是分类待办，不要求图片已经下载成功。

究极技能书通常不可掉落，建议人工归入黑名单；`雪糕投手-究极技能书`是已确认的例外。初级、高级、终极可掉落不能推断究极也可掉落。

## 失败样本边界

失败样本位于 `logs/match_failed/loots/unknown_ID_次数.png`，文件名末尾表示相同图块累计识别失败次数。

- 完美符合：沿用既有阈值，完全一致率至少 98%、一致特征像素至少 40、领先次选至少 3%。只有未分类物品的完美样本累计次数达到 2 次才额外建议加入白名单；基本符合样本不计入该次数。
- 基本符合：可能受数量、卡片、子弹或火苗遮挡，人工确认后可以清理相应失败日志。
- 完全不置信：保留等待人工检查，可能是活动道具、截图异常或严重遮挡。

建议只供维护者确认，不自动将建议物品加入白名单。主工具不删除或重命名失败日志；不能因修改名单或更新模板而直接删除历史日志。黑名单图片最终不留存，因此清理后无法持续用它们发现黑名单实掉冲突。

运行中的 FAA 需要刷新图片资源或重启才能使用磁盘中新替换的图片。

## 辅助源码

- `workflow.py`：主流程编排。
- `matching.py`：匹配特征、置信度与多次完美符合建议。
- `sync.py`：名单排序、图片校验与同步底层操作。
- `__main__.py`：标准命令行入口与图片下载。
- `classification.py`：Excel 解析、ID 分类与路径常量。
- `function/common/loot_policy.py`：工具与运行时共用的名单协议。
- `diagnostics.py`：需要详细归因时单独运行，生成 CSV/HTML；默认主流程不生成这些详细表。
- `compare.py`：手动诊断目录差异，不作为资源入库条件。“相同”仅指名称相同。
- `classify.py`：人工目录分类辅助；移动分类时需同步维护名单，之后运行标准入口。
