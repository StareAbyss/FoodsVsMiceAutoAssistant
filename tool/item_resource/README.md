# 战利品资源与失败样本处理规范

本目录负责战利品 CDN 资源下载、分类、正式资源对比，以及 `logs/match_failed/loots` 失败样本的离线归因。

这份规范是失败样本的固定处理方针。修改 `analyze_failed_loot_images.py` 的分级、报告或清理逻辑时，必须保持这些业务边界；不能仅凭一个相似度数值自动复制或删除文件。

## 数据来源与含义

- 最新候选资源：`resource_other/图像资源_战利品_最新资源/`
- 正式识别资源：`resource/image/item/战利品/类型/名称.png`
- 不会掉落黑名单：`resource/image/item/无法掉落道具名单.csv`
- 失败样本：`logs/match_failed/loots/unknown_ID_次数.png`
- 离线报告：`resource_other/战利品识别失败分析/`

失败文件名末尾的“次数”表示完全相同的图块累计识别失败了多少次，不表示它现在仍会失败，也不表示连续失败次数。FAA 只会创建新失败文件或增加计数；以后补入正确模板时，不会自动重新归因或删除旧日志。

## 固定的三种匹配结论

| 匹配结论 | 常见图像表现 | 主要用途 | 固定处理方式 |
|---|---|---|---|
| 完美符合 | 候选物品有效特征区几乎完全一致，且明显优于次选 | 确认某个实际掉落物品尚未纳入识别 | 核实分类和黑名单；复制干净 CDN 图到正式库；验证资源加载；成功后清理对应失败日志 |
| 基本符合 | 主体特征明确，但局部像素被数量、卡片、子弹、火苗等覆盖 | 找出已经有模板、但因遮挡而失败的样本 | 输出待确认清单；维护者明确确认后才允许清理；不降低全局阈值，不把遮挡图作为模板 |
| 完全不置信 | 没有足够特征，或多个候选差距很小 | 保留活动道具、截图异常和未知物品线索 | 保留原日志，交给维护者人工查看；禁止自动删除或自动加入正式库 |

数值阈值只是实现三种业务结论的手段。后续即使调整算法，也必须保留“完美符合可补模板、基本符合待确认、完全不置信保留”的处理语义。

## 各种情况的可能性与处理方式

### 1. 完美符合，正式识别库没有，黑名单也没有

可能性：

- 新活动或新关卡加入了实际可掉落物品。
- CDN 已经有干净图片，但 FAA 正式库尚未更新。
- 原资源分类或迁移时发生遗漏。

处理：

1. 确认失败样本来自 `logs/match_failed/loots`，而不是宝箱、背包或其他界面。
2. 核对候选分类、名称、44×44 尺寸和 alpha 通道。
3. 将干净 CDN 图片复制到正式识别库对应分类，禁止复制带数量或特效的失败截图。
4. 检查目标不存在，复制后校验源与目标哈希。
5. 刷新资源或重启 FAA，确认模板进入运行时候选。
6. 完成以上步骤后，清理该物品对应的失败日志。

### 2. 完美符合，但正式识别库已经存在

这是正常的历史状态，不等于当前识别逻辑仍然有问题。常见可能性：

- 失败日志生成得更早，模板后来才加入正式库。
- 正式模板后来被更换成了正确版本，但旧日志没有自动清理。
- 复制模板时 FAA 已经在运行，磁盘文件存在，但进程内 `RESOURCE_P` 和匹配缓存尚未刷新。
- 文件虽然存在，但分类、重名覆盖或黑名单导致它没有进入实际运行时候选。
- 样本含少量数量/特效差异，当前干净模板能识别正常掉落图，但仍不能识别同样的遮挡图。

处理：

1. 比较失败日志时间和正式模板时间；日志更早时优先按历史日志处理。
2. 检查黑名单、分类路径和运行时平铺资源中是否真的包含该名称。
3. 重启 FAA 或明确调用资源刷新，再用当前正式逻辑回放。
4. 当前正常图能够识别后，可以清理历史失败日志；不要重复复制同名模板。
5. 如果刷新后未遮挡图仍失败，继续排查资源加载、同名覆盖、alpha、掩模和图片版本，不能直接删日志。

### 3. 完美符合，但候选位于不会掉落黑名单

可能性：

- 黑名单维护错误或已经过时。
- 同名物品存在不同场景或不同版本，当前名称不足以区分。
- 失败目录或截图切分来源异常，实际并非战利品结算界面。

处理：

1. 人工查看失败图和整板战利品截图，确认确实来自掉落结果。
2. 确认后从黑名单删除对应的“类型,名称”条目。
3. 如果正式库缺图，同时补入干净模板。
4. 验证运行时不再过滤该模板后，再清理对应失败日志。

### 4. 基本符合，正式识别库已有

常见遮挡来源：

- 右下角掉落数量数字。
- 战斗结算时残留的卡片、子弹、火苗或其他动画。
- 半透明光效、边缘扰动或截图时序差异。

处理：

- 只生成 `基本符合_待确认清理.csv`，不自动删除。
- 维护者确认候选物品正确后，可以直接清理对应失败日志。
- 不新增重复模板，不使用遮挡图作为模板，也不为了单个遮挡样本降低正式识别的全局阈值。
- 如果同一种遮挡大量重复出现，应单独研究遮挡鲁棒性或截图时机，不能无限收集脏模板。

### 5. 基本符合，但正式识别库没有

可能是新物品恰好又被遮挡，也可能是相似物品造成的误归因。

处理：

- 不直接补入，也不直接删除。
- 等待同物品的完美符合样本，或由维护者结合整板截图和活动信息确认。
- 确认后仍然只使用干净 CDN 图作为正式模板。

### 6. 完全不置信

常见可能性：

- 候选资源范围外的活动道具或临时货币。
- CDN Excel 尚未收录，或目标条目没有可用下载 URL。
- 图片不是 44×44 战利品资源，尺寸或来源错误。
- 截图区域偏移、空格子、结算界面未稳定或切分错误。
- 严重遮挡使物品主体特征不足。
- 截到无关 UI、动画帧或异常透明图。

处理：

- 保留日志供人工检查，不自动清理。
- 如果确认是新活动掉落，先寻找干净 44×44 CDN 资源；找不到时再设计人工取图流程。
- 如果确认是截图错误，排查截图时机和分块坐标后，由维护者手动清理。

### 7. CDN 有候选，但没有可靠失败样本

CDN 中存在某个物品，不代表它能从战利品界面掉落。它可能是未实装资源、商城/背包物品、其他系统素材或仅特定活动使用。

处理：

- 保持在 `仍待实掉验证候选.csv`。
- 没有战利品实证前，不自动加入正式识别库。
- 维护者人工审核游戏内“掉落预览”并明确指出物品名称和技能书等级时，可以把该审核视为实掉范围证据；即使没有个人掉落日志，也可按维护者指定的等级手动迁移干净 CDN 图片。
- 人工预览只证明明确展示的等级。例如预览确认初级、高级、终极时，只迁移这三个等级，不能顺带推断究极技能书也会掉落。
- 这类迁移没有对应失败日志，不执行日志清理；迁移后仍需检查分类、黑名单、文件哈希和运行时资源刷新。
- 已明确不会掉落时加入黑名单，并记录正确分类和名称。

#### 究极技能书的默认规则

- 究极技能书几乎不会作为战利品掉落，因此新获取的究极技能书资源默认加入不会掉落黑名单，不进入正式识别库。
- `雪糕投手-究极技能书` 是目前唯一由失败战利品样本证实的孤例：保留在正式识别库，且不得加入黑名单。
- 初级、高级、终极技能书可掉落，或游戏内预览展示了这三个等级，都不能作为究极技能书可掉落的推断依据。
- 如果以后发现新的究极技能书实掉证据，应只解除该物品自己的黑名单条目，再把干净 CDN 图加入正式识别库并按“完美符合”流程处理；不改变其他究极技能书的默认状态。

### 8. 无 URL 或图片尺寸不兼容

处理：

- 无 URL 条目保留在下载清单中，不用其他同名图片冒充。
- 非 44×44 图片保留在 `尺寸不兼容候选.csv`，不能直接缩放后加入正式库。
- 应寻找对应的战利品规格 CDN 图，或确认该资源本来就不属于战利品图标。

## 删除边界

- 完美符合：仅在干净模板已加入、黑名单状态正确并完成验证后，删除对应失败日志。
- 基本符合：仅在维护者明确确认本批清单后删除。
- 完全不置信：默认永久保留，等待维护者手动处理。
- 删除必须按报告中的精确文件名逐个执行，先确认所有绝对路径都位于 `logs/match_failed/loots`。
- 不使用目录递归删除，不按模糊文件名或物品名通配删除。
- 失败日志通常不受 Git 追踪，永久删除后不能通过 Git 恢复；删除后要报告文件数和累计次数。

## 资源刷新与验证

正式资源会在 FAA 初始化时加载到 `RESOURCE_P`，战利品匹配又有预处理缓存。因此在 FAA 运行期间直接复制文件，不保证当前进程立即看见新模板。

推荐验证顺序：

1. 对比正式库和最新资源，确认新增数量、缺失数量和黑名单数量符合预期。
2. 校验复制后的文件哈希和 44×44 BGRA 格式。
3. 重启 FAA，或通过明确的资源刷新流程替换 `RESOURCE_P`。
4. 确认新名称出现在运行时战利品候选中。
5. 刷新离线分析报告；已补入的新物品不应继续出现在“建议补入正式识别资源”中。

## 工具分工

- `download_item_resources.py`：从 Excel 提供的 CDN 路径获取分类资源。
- `compare_loot_resources.py`：对比最新候选、正式资源和黑名单。
- `classify_loot_resources_once.py`：按 Excel 规则一次性迁移已有正式资源分类。
- `analyze_failed_loot_images.py`：按本规范对失败样本分级并生成复核清单，不自动复制或删除资源。
