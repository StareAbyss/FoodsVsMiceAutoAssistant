# AI 工作总则

本文说明协作方式和完成标准。通用约束见根目录 [AGENTS.md](../../AGENTS.md)，具体操作方法按本目录 `README.md` 查阅。

## 信息优先级

处理任务时按以下优先级判断：

1. 用户在当前任务中的最新明确要求。
2. 当前源码、配置、资源、测试和实际调用链。
3. 仓库内对应专项文档。
4. 旧聊天历史、经验和未经验证的推测。

如果文档与当前实现冲突，应核对真实行为并指出冲突；不能为了符合旧文档而直接覆盖用户的新实现。

## 协作原则

* 默认把实现请求完成到修改、验证和结果说明；用户明确要求“先说计划”时才停在方案阶段。
* 不擅自回滚、覆盖或整理用户已有改动。无关内容应隔离，相关内容应保留原意后整合。
* 修改前先找到真实入口、配置来源、数据生成位置、运行时消费位置和打包路径，避免只修表面调用点。
* 功能按可以独立说明、验证和回滚的边界拆分；纯格式修改不能掩盖功能差异。
* 用户指定文件范围、标题措辞、保留项或“不恢复”内容时，按用户原话执行。
* 新增运行时配置或资源格式时，同时检查生成器、读取方、默认模板、打包流程和测试。
* 声称一个参数影响多个阶段时，应逐条核对每条调用链。例如“自动携带”和“智能使用”必须分别验证。
* 测试范围与风险匹配。无法运行的检查、依赖外部环境的行为和仍需用户裁定的事项必须明确说明。

## 完成标准

任务完成至少满足：

* 用户要求的行为已经实际实现，不只停留在说明或半成品。
* 相关调用链、配置和资源边界已经核对。
* 已执行最小但有效的测试与格式检查，或明确说明无法执行的原因。
* 没有夹带与当前任务无关的工作区改动。
* 对外行为、开发流程或数据格式发生变化时，对应专项文档已经同步。
