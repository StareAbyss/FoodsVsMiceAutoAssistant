# 游戏窗口操作与识图人工校验

本文适用于需要一边操作真实游戏窗口、一边开发或校验 FAA 自动化流程的任务，例如进入指定界面、点击按钮、截取模板、确定识图范围，以及向用户提供红框/绿框测试图进行人工验收。

这类任务应优先复用 FAA 已有的窗口句柄、后台截图、模板匹配和动作队列，不要先用桌面坐标、前台鼠标或通用截屏重新实现一套流程。

## 开始前先确定边界

1. 明确本次是一次性测试，还是需要修改生产流程。
   - 用户只要求测试或标注图时，不要把临时脚本写进 `function/`，也不要顺手修改业务代码。
   - 确认了坐标、选区或阈值且用户要求实装后，才修改业务函数。
2. 先在源码中查找已有导航函数、截图函数和相似业务案例。
   - 优先查找 `action_goto_*`、`match_p_in_w`、`loop_match_p_in_w`、`capture_image_png` 和相邻任务事项。
   - 已有函数如果会继续创建房间或开始战斗，不要为了复用而执行多余步骤；可以补一个只停留在目标界面的窄职责函数。
3. 对购买、兑换、删除物品等有副作用的界面，测试只走到识别完成。
   - 不点击最终“确定”或“购买”。
   - 截图和匹配完成后点击“取消”，恢复安全状态。
   - 不要把“二级密码可能拦住”当作唯一保护措施。

## FAA 窗口层级和句柄

句柄获取入口位于 `function/scattered/gat_handle.py`：

```python
from function.scattered.gat_handle import faa_get_handle

handle_360 = faa_get_handle(channel=channel, mode="360")
handle_browser = faa_get_handle(channel=channel, mode="browser")
handle_flash = faa_get_handle(channel=channel, mode="flash")
```

三种句柄的用途：

| 句柄 | 用途 |
| --- | --- |
| `360` | 最外层 360 游戏大厅窗口；常作为 `root_handle` 检查最小化状态 |
| `browser` | 服务器选择和浏览器内容层 |
| `flash` | 实际游戏客户区；游戏内截图、识图和点击通常使用它 |

注意事项：

- 游戏刷新、重新登录或 Flash 重建后，`flash` 句柄会变化，必须重新调用 `faa_get_handle()`，不能复用旧句柄。
- 未进入服务器时 `flash` 可能为 `0`，此时应检查 `browser` 或 `360` 画面，不要继续对句柄 `0` 截图或点击。
- FAA 业务坐标通常基于 Flash 客户区的 `950 × 600` 标准坐标。不要把 360 外框、标题栏或浏览器工具栏坐标混进游戏坐标。
- 双号窗口必须分别按各自 `channel` 获取句柄；不要根据窗口排列猜测 1P/2P。

## 后台截图

使用 `function/common/bg_img_screenshot.py`：

```python
from function.common.bg_img_screenshot import capture_image_png

image = capture_image_png(
    handle=handle_flash,
    root_handle=handle_360,
    raw_range=[0, 0, 950, 600],
)
```

返回值是 NumPy 图像，通常为 BGRA 四通道。保存中文路径时，优先使用 OpenCV 编码后写入，避免 `cv2.imwrite()` 的中文路径兼容问题：

```python
import cv2

cv2.imencode(".png", image)[1].tofile(str(output_path))
```

截图后的最低检查项：

- 句柄不是 `0`。
- 图像尺寸符合预期，不是空数组或全黑图。
- 当前确实处于目标界面；每次会改变界面的点击之后重新截图，不使用旧截图推断新状态。
- 如果目标窗口最小化，传入 `root_handle=handle_360`，让现有截图函数按项目逻辑尝试恢复。

## 后台操作

生产代码优先通过动作队列点击：

```python
from function.globals.thread_action_queue import T_ACTION_QUEUE_TIMER

T_ACTION_QUEUE_TIMER.add_click_to_queue(
    handle=handle_flash,
    x=target_x,
    y=target_y,
)
```

动作队列负责与 FAA 的并发操作和缩放设置配合。不要在生产业务中用即时点击绕过队列。

一次性人工诊断脚本可以使用 FAA 的后台点击原语：

```python
from function.common.bg_mouse import mouse_left_click

mouse_left_click(handle=handle_flash, x=target_x, y=target_y)
```

它适合用户明确允许的临时界面导航，但不能因为方便就复制进正式业务函数。每个关键点击之后都应等待界面加载并重新截图确认；固定坐标只应来自已经验证过的同分辨率界面。

## 模板匹配和点击

单次识别使用 `match_p_in_w()`：

```python
from function.common.bg_img_match import match_p_in_w

status, relative_top_left = match_p_in_w(
    source_img=image,
    source_range=scan_range,
    template=template,
    match_tolerance=0.95,
    return_center=False,
)
```

状态码含义：

- `0`：识图过程出现错误。
- `1`：没有达到阈值。
- `2`：识别成功。

`source_range` 格式统一为 `[left, top, right, bottom]`。当传入 `source_range` 时，`match_p_in_w()` 返回的是相对于该选区的坐标。计算全窗口实际命中矩形时必须加回选区原点：

```python
template_h, template_w = template.shape[:2]
match_left = scan_range[0] + relative_top_left[0]
match_top = scan_range[1] + relative_top_left[1]
match_rect = [
    match_left,
    match_top,
    match_left + template_w,
    match_top + template_h,
]
```

等待目标并在命中后点击，优先使用 `loop_match_p_in_w()`：

```python
from function.common.bg_img_match import loop_match_p_in_w

found = loop_match_p_in_w(
    source_handle=handle_flash,
    source_root_handle=handle_360,
    source_range=scan_range,
    template=template,
    match_tolerance=0.95,
    match_interval=0.2,
    match_failed_check=2,
    after_sleep=1,
    click=True,
)
```

`loop_match_p_in_w()` 内部会把识别出的相对中心坐标加回 `source_range` 原点后交给动作队列，不要在外面重复加坐标偏移。

## 识图选区的统一计算规则

先在真实游戏截图中取得模板的实际命中矩形，再计算业务选区。默认规则是实际命中位置四周各扩 `10px`：

```python
padding = 10
scan_range = [
    match_rect[0] - padding,
    match_rect[1] - padding,
    match_rect[2] + padding,
    match_rect[3] + padding,
]
```

例如实际命中位置是：

```text
[485, 362, 563, 393]
```

则识图选区必须是：

```text
[475, 352, 573, 403]
```

不要凭肉眼随意扩大到整个弹窗。过大的选区会增加误识别、重复目标和未来 UI 变化带来的风险。

以下情况可以偏离 `10px` 规则，但必须在测试图或日志中说明理由：

- 动画造成目标位置实际漂移。
- 不同服务器或 UI 状态存在已验证的位置差异。
- 目标边缘会被鼠标悬停、特效或遮挡改变。

按钮存在“默认/被选中”等多种外观时：

- 为每种外观保留独立模板。
- 使用同一个经过验证的紧凑选区。
- 测试时记录最终命中的是哪张模板。
- 多张价格安全图高度相似时，应使用更高阈值并要求只唯一命中一张；无法唯一确认时只允许取消。

## 生成红框/绿框人工校验图

用户需要人工检查时，至少提供以下两层框：

- 红框：业务代码真正使用的 `scan_range`。
- 绿框：本次真实截图中模板实际命中的 `match_rect`。

推荐同时提供全局上下文和局部放大图，并在图中或回复中标明：

- 模板文件名。
- 匹配度和业务阈值。
- 红框、绿框的四个坐标。
- 绿框到红框四边的实际余量。
- 本次处于默认、悬停、选中或其他哪一种 UI 状态。

最小绘制示例：

```python
import cv2

test_image = image.copy()

# OpenCV 使用 BGR：红色为 (0, 0, 255)，绿色为 (0, 255, 0)。
cv2.rectangle(
    test_image,
    (scan_range[0], scan_range[1]),
    (scan_range[2], scan_range[3]),
    (0, 0, 255),
    2,
)
cv2.rectangle(
    test_image,
    (match_rect[0], match_rect[1]),
    (match_rect[2], match_rect[3]),
    (0, 255, 0),
    2,
)
```

如果制作局部放大图，红框和绿框必须使用同一套坐标变换，不能在缩放后凭肉眼重画：

```python
display_x = paste_x + (source_x - crop_left) * scale
display_y = paste_y + (source_y - crop_top) * scale
```

人工校验图完成后，必须用可查看本地图片的工具实际打开成品，检查：

- 两个框没有画反。
- 框线没有因裁剪或缩放错位。
- 标签没有遮住关键目标。
- 图片展示的是本次新截图和新模板，而不是旧的缓存结果。

## 测试文件和产物位置

可复现的诊断脚本应放入对应的 `test/<topic>/` 子目录。生成的截图和标注图使用：

```python
from test.output_paths import get_test_output_dir

output_dir = get_test_output_dir("magic_tower_purchase")
output_path = output_dir / "cancel_button_recognition_region.png"
```

一次性、仅适用于当前电脑或账号的脚本和截图不应提交到 Git。不要把测试截图放进 `resource/image/`，除非它已经被用户确认并将作为正式识图模板随版本发布。

独立测试脚本需要加载图片资源时，注意 `fresh_resource_img()` 会重新绑定资源字典。应从模块属性读取刷新后的对象：

```python
from function.globals import g_resources

g_resources.fresh_resource_img()
template = g_resources.RESOURCE_P["common"]["目标目录"]["目标.png"]
```

不要先 `from function.globals.g_resources import RESOURCE_P`，再调用 `fresh_resource_img()` 后继续使用旧的局部引用。

## 推荐的完整工作顺序

1. 阅读本文件，并搜索现有相似流程和导航函数。
2. 明确用户允许操作哪个游戏窗口，以及测试必须停止在哪一步。
3. 使用仓库虚拟环境从项目根目录运行测试：

   ```powershell
   .\.venv\Scripts\python.exe test\<topic>\test_<name>.py
   ```

4. 获取 `360`、`browser`、`flash` 句柄；`flash == 0` 时先处理登录/刷新状态。
5. 使用 FAA 后台操作进入目标界面；每次界面变化后重新截图验证。
6. 在真实截图上匹配每一种模板状态，记录模板名、阈值和实际命中矩形。
7. 按实际命中矩形四周各扩 `10px` 计算业务选区。
8. 生成红框/绿框总览和必要的局部放大图，实际打开成品检查。
9. 将坐标、匹配度、模板状态和四边余量交给用户确认。
10. 对有副作用的弹窗点击“取消”退出。
11. 用户确认后才把选区或流程写入业务代码，并进行 AST/编译检查与相关回归测试。

如果运行环境限制 Win32 句柄读取或后台截图，应为具体、最小范围的命令请求权限，并说明只读截图或将要点击的明确界面步骤。不要用更宽泛的系统权限绕过限制。

## 常见错误

- 游戏刷新后仍使用旧 `flash` 句柄。
- 从 `360` 截图取得坐标，却拿去点击 `flash` 客户区。
- `match_p_in_w()` 返回相对选区坐标后，忘记加回选区原点。
- 已经加回原点，又在 `loop_match_p_in_w()` 外重复加一次。
- 用过大的弹窗范围代替“命中矩形 ±10px”。
- 只测默认按钮，没有测试悬停或选中模板。
- 多张安全价格图都超过宽松阈值，却任选第一张继续确认。
- 用户只要求测试，却把一次性脚本或坐标直接写进生产模块。
- 标注图只画选区，没有画实际命中位置，用户无法判断余量。
- 生成标注图后没有实际打开检查，导致红绿框颜色、缩放或坐标错误。
- 测试完成后遗留购买弹窗，或误点最终确认按钮。
