# 复杂关卡实战测试入口

这个入口用于人工验证任务卡、禁用卡、限卡、自动带卡和微调方案等组合行为。它直接复用 FAA 的正式战斗调度，不会启动任务序列，也不会登录或刷新游戏。正式流程在异常恢复分支中提出的刷新请求也会被测试入口拦截，并在控制台留下提示。

## 使用前准备

1. 停止 FAA 主程序中正在执行的任务，避免两个进程同时操作游戏。
2. 提前打开 `config/settings.json` 对应的两个角色窗口。
3. 两个角色都停留在 FAA 正常开始任务时的游戏初始界面。
4. 打开 `main.py`，在 `main()` 函数开头的 `config` 字典中填写本次关卡参数。

方案字段既可以填写文件名，也可以填写 UUID；文件名不需要 `.json`。`deck=0` 表示自动带卡，`deck=1..6` 表示手动卡组。若要严格使用测试文件中的 1P、2P 和微调方案，应保持 `global_plan_active=False`。

常规双人关卡通常使用 `player=[2, 1]`，代表 2P 房主、1P 队友；单人测试使用 `[1]` 或 `[2]`。正式流程对跨服和魔塔等特殊地图仍会执行原有修正。

## 运行

在 PyCharm 中直接运行 `main.py` 的 `main()`，脚本会读取当前 `config/settings.json`，进入地图、跳转关卡并完成配置中的战斗。全部常用参数都和入口放在同一个函数内，不需要打开其他配置文件。

首次实战前可以在项目根目录仅做校验：

```powershell
uv run python -m test.complex_battle_runner.main --check
```

仅校验模式会检查 JSON、方案引用、UUID 冲突以及两个游戏窗口句柄，不会产生任何游戏点击。

## 配置注意事项

- `quest_card=None` 表示没有任务卡。
- `ban_card_list=[]` 表示不额外禁卡。
- `max_card_num=None` 表示不限卡；填写 1 或 2 时，正式任务入口会修订为 3。
- `dict_exit` 控制战斗完成后的退出动作；特殊地图可能由正式流程覆盖。
- 测试入口只读加载方案。若检测到 UUID 冲突，会停止并列出两个文件，不会自动改写方案。
